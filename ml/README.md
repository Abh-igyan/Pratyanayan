# AI Recovery Predictor (Day 1)

This module is intentionally isolated from the live Razorpay backend and the non-AI baseline benchmark. It creates a separate synthetic data pipeline for training a supervised recovery-success model.

## Why synthetic data is required

The project already includes a deterministic benchmark with 1,000 unseen evaluation cases and a fixed seed of 42. That benchmark is a protected evaluation set and must remain untouched. We do not train on it.

For the first ML iteration, we need a much larger and more diverse training population so the model can learn patterns in payment-failure recovery behavior.

## Why the benchmark remains unseen

The seed-42 benchmark is used for final evaluation and fairness. Keeping it unseen prevents accidental data leakage, benchmark overfitting, and optimistic metrics that do not reflect real generalization.

## Feature schema

Each row represents a failed-payment opportunity available before a recovery decision is made.

Current payment features:
- amount
- payment_method
- failure_code
- attempt_number
- time_since_failure

Customer history features:
- customer_total_orders
- customer_successful_orders
- customer_failed_orders
- customer_success_rate
- customer_failure_rate
- customer_average_order_value
- customer_total_spend
- customer_last_success_age
- customer_last_failure_age

Payment-method history features:
- customer_method_attempts
- customer_method_successes
- customer_method_failures
- customer_method_success_rate

Other context:
- customer_history_segment
- order_value_percentile_for_customer

Target:
- recovery_success: 0/1

This target indicates whether a subsequent legitimate recovery attempt would succeed. It is generated using an independent synthetic environment and not by the deterministic baseline policy.

## Leakage prevention

The model only ingests features available before the recovery decision. No post-recovery variables or webhook responses are included.

Train/validation/test splits are performed by customer_id so repeated transactions from the same synthetic customer do not leak across splits.

## Synthetic ground truth generation

The target is generated by a nonlinear synthetic environment that depends on realistic interactions among:
- failure type
- customer history segment
- payment method
- success rate
- failure count
- attempt number
- time since failure
- amount

The target is created by a logistic-style latent score with nonlinear interactions and added randomness; it is intentionally not a mirror of the deterministic baseline policy.

This makes the synthetic world realistic but not designed to favor any single model.

## Why CatBoost is used

CatBoost is well suited for mixed tabular data with categorical variables such as:
- payment_method
- failure_code
- customer_history_segment

It captures nonlinear relationships without requiring manual one-hot encoding in the main model path.

## Why Logistic Regression is included

Logistic Regression is a simple interpretable benchmark. It helps verify whether CatBoost is learning actual nonlinear structure rather than just fragile linear patterns.

## Evaluation methodology

We evaluate on a held-out test split using:
- ROC-AUC
- PR-AUC
- precision
- recall
- confusion matrix
- Brier score
- calibration
- predicted probability distribution

We also report business-oriented metrics:
- recovery attempts selected
- recovered orders
- recovered revenue
- revenue recovery rate
- intervention rate

## Limitations of synthetic data

This is still synthetic data. It is useful for building a first learning pipeline and comparing model families, but it does not capture the full complexity of real Razorpay merchant behavior. Synthetic ground truth can still be a strong benchmark for experimentation and feature engineering before any production or agent integration.

## Usage

```bash
python -m ml.train
```

This command generates synthetic training data, creates group-based customer splits, trains Logistic Regression and CatBoost, evaluates both models, saves the CatBoost model under ml/model, and prints a concise comparison.
